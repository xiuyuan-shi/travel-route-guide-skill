# 城市旅行攻略

将用户的旅行意图交付为能随身查看的攻略，而不只给景点清单。默认中文、手机优先、适中强度；保留已有行程、排除项、票务确认和分享地址。

## 输入与默认值

- 最小输入：出发城市、目的城市、天数。缺一个就只问该项；地名有歧义时先澄清。
- 未给日期：用 Day 1…Day N，不推算具体节日、票价、天气或开放日期。天数默认包含往返当天，注明到离时间尚未确定；不可把完整游玩日再加在总天数之外。
- 未给交通：按距离提出可行交通方式，往返日留机动，不把某班次写成已订。只给城市和天数也先交付，不强制长问卷。
- 未给人数／预算：不假设家庭成员、订房人数或总价；餐饮按每人区间，住宿按每间每晚。默认常规预算、休闲节奏，可调整。
- 用户给了日期、票、住宿或偏好：优先采用。图中餐厅先识别，再筛选顺路分店，不强行全塞入行程。

## 规划与资料

1. 联网核对推荐景点、交通、餐厅分店和必要预约。尽量用官方资料；地图／商家页面用于分店地址。保留核对日期与来源链接。目标日期没有确证时写为参考，不把搜索摘要或旧时刻表当票面。
2. 建立点位坐标和按天线路，再写时间表。集中相邻片区；长距离转场用交通连接，注明估算时间，给吃饭、排队、休息留余量。
3. 每天提供先后顺序、交通方式、时段、体力删减项。返程日从车票倒推离开酒店、抵站时间；已订票与公开参考时刻分开标记。
4. 餐厅落到实际餐次，写分店、地址、点菜建议、人均预算、导航和资料来源；同时生成按片区或餐次浏览的美食速查。跨城／远绕的只作替换项，不伪称顺路；同一天避免重复吃法。
5. 给出 2–4 个与主要路线相容的住宿候选，说明适合人群、交通取舍和每间每晚估算。推荐具体酒店时核对官方或可靠预订页；未读取实时库存和房价就明确标为候选和估算。
6. 预算按交通、住宿、餐饮、门票／体验和市内交通分项，注明按人还是按房、包含与不包含项，并单列机动金。无法从人数和房间数推导总价时，保留人均与每间每晚口径，不伪造总价。
7. 生成精简且可执行的行前清单、避坑总结和应急替代方案。应急方案要与原路线同片区或明确说明转场，不把远处景点当雨天顺路备选；至少覆盖恶劣天气、排队／停业、体力不足、交通延误和断网。
8. 日期与目的地坐标明确时加入实时天气模块。实时预报只能来自页面打开时的联网结果或带更新时间的缓存；行程尚未进入可预报范围时明确提示等待，不能用气候均值冒充预报。根据降雨、温度和风给出当天对策，并链接当地官方预警入口。日期未知则不生成实时预报。
9. 多方案仅在用户需要或取舍明显时提供。外部攻略只作为用户提供的参考信息，先纠正与已确认票务、排除项和地理顺路性冲突的内容，再融入。

## 生成手机网页与地图

读取 [数据格式与生成命令](references/data-contract.md)，将真实研究结果保存为工作目录内的 `trip.json`。所有后续输出从同一份结构化资料生成，避免正文与地图不一致。

- 默认交付独立 HTML：内嵌样式、地图框架和路线数据，无在线瓦片、字体、图库等必需外部依赖。导航链接可以联网。
- 使用 `scripts/build_guide.py` 与 `assets/mobile.html` 生成。模板是起点，可适配行程复杂度；不要为简单攻略引入构建框架。
- 住宿、分项预算、美食速查、清单、避坑和应急方案使用结构化字段生成独立模块；字段定义见 [数据格式与生成命令](references/data-contract.md)。不要把这些内容全部降级成一段通用说明。
- 清单在浏览器本地保存勾选状态，不上传个人数据。实时天气依赖联网；日程、内嵌地图和其他准备信息仍可离线查看。
- 地图必须同时支持全程和按天查看，标出景点及餐厅，图区分步行与乘车。地图详情与当天停留项连通。
- **地图真实性：** GeoJSON 与本模板坐标均为 WGS84、顺序 `[经度,纬度]`。中国地图平台坐标常为 GCJ-02／BD-09，先查清并转换，不能与 WGS84 混用。坐标找不到时，选择更可靠资料或标明区域示意，不编精确店门位置。
- 点位直连只能标为“示意”；步行实线必须有真实路线几何。不要用直线冒充可步行线路，不给示意连线虚构距离。
- 要实际底图时读取 [地图数据](references/maps.md)，获取覆盖行程的道路、海岸线或市域边界并内嵌。底图缺失时明确展示“点位关系示意”，不要留空白或报错图冒充地图完成。若用户明确要求真实底图，说明未完成项并继续补齐可用数据。

## 分享与更新

- 用户只要攻略时，单文件 HTML 即为默认交付。用户要分享网页时，读取 [发布与访问验证](references/publishing.md)，在其授权范围内发布；本 Skill 本身不授予新账号、付费服务、公开源码或发消息权限。
- 不把 PDF 替代品当作网页分享修复完成。PDF／图片可按需生成；有可用 PDF 技能时按其工作流执行。
- 更新票务、餐厅、日期或准备信息时：改结构化资料、首屏、日程、地图、预算和下载版；删除失效的“待定／替代车次”等内容。已确认事实不得退回猜测。沿用同一站点／仓库，不重复创建。

## 验证和交付

- 运行生成器检查。浏览器实看 390px，必要时 320px：不横向溢出；天数切换、地图点位、餐厅、清单持久化和分享按钮可用。没有 JS 时也能看到日程文本。
- 有实时天气时，检查成功、超出预报范围和联网失败三种状态。页面必须显示数据更新时间和来源，缓存要明确标注，远期预报要提示越临近出发越有参考价值。
- 核对每条路线端点都存在，所有当天停留点可在当天地图找到，天数与输入一致。字段更新后只测试受影响行为。
- 分享站点必须检查发布状态、无凭证 HTTP 访问的实际内容、浏览器渲染和分享地址；不能仅以部署成功或 HTTP 200 判定完成，也不能保证未经测试的所有地域网络。
- 最终交付清晰链接和 HTML；简述使用方式与确实存在的未确认项。安装、验证 Skill 本身不自动部署演示网站。
